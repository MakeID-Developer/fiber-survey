## 1. 目标与范围

将原 `app` 中“信测对纤仪 / TR-FID-”业务移植至新建独立 Android App，保留主要操作和调试功能，方便内部联调和提交第三方参考。第三方应只需本工程和配套SDK交付物，不需原综合测试App及无关设备模块。

### 1.1 本次必做

1. 扫描 `TR-FID-` 主机，显示名称、MAC、主机编号和RSSI，用户选择后连接。
2. 根据手工输入的主机编号连接，同时接受编号和完整主机名。
3. 展示扫描、连接、服务发现、通知就绪、断开等状态，以及实际MTU和单包载荷。
4. 接收功率变化、探测器开机/关机事件；支持本地有界事件列表和清空。
5. 手工配置探测器ID白名单、显示过滤状态、清空恢复全部放行。
6. 用户确认后发送“一键关机”，处理ACK、拒绝、超时、断线与释放结果，不自动重试。
7. 展示本地TX/RX JSON和状态/错误日志，有界存储、可清空；支持手工开关原始日志。
8. 完整权限、连接/页面生命周期、重复操作限制、会话隔离及资源清理。
9. 独立AAR依赖配置、使用说明、依赖与版本清单、后续验证记录。

### 1.2 非本次范围

- 不迁移智能锁、电子钥匙、USB锁、清虚仪、RFID、网关、测速仪或其他设备入口。
- 不接入 `MkdLockLib`、`MkdElectronicKeyLib`、`MkdFiberClearLib`；本SDK不需要锁库AppID/AppSecret，不复制另一Demo的鉴权凭证。
- 不添加登录、Token、平台请求、设备云绑定、Bugly/崩溃上传、自动升级、在线帮助或埋点。
- 不自行实现BLE协议、JSON分包、GATT读写或重复引入底层SDK内部Helper。
- 不新增固件升级、后台常驻扫描、自动重连、连接就绪自动关机、循环关机、功率数值测量或曲线展示。
- 本次只规划中文界面与开发文档；SDK已有英文接口资料可随包提供，不等于App英文UI已完成。

本App采用**运行时离线**设计：只通过BLE与主机通信，不发起IP网络请求。开发时Gradle下载依赖不属于App运行行为；完全离线构建需要另交付许可允许的外部依赖仓库，不能只凭本地AAR宣称已支持。

## 3. 方案与页面组织

### 3.1 采用的迁移方式

| 方案 | 评价 | 结论 |
| --- | --- | --- |
| 整个旧app复制后隐藏无关入口 | 迁入网络组件、全局配置和无关SDK，资源耦合难清理 | 不采用 |
| 只提取xcfiber页面/资源，增加薄Controller和独立AAR配置 | 保留熟悉界面和直接SDK调用，能补齐状态与生命周期 | **采用** |
| 重新做插件化/多模块通用设备平台 | 对单设备参考App过重 | 不采用 |

技术栈：Java + XML + ViewBinding + RecyclerView。保留新工程AGP/Gradle工具链，不添加Compose；UI依赖可依据实际AAR的minSdk约束统一兼容版本，不强行overrideLibrary。公共逻辑只拆到有明确职责的类，不为了架构把一个按钮分成多层Repository。

### 3.2 界面布局默认方案

参考已有Demo风格，业务主页面直接作为启动首页，不再保留无意义的“Hello World → 第二首页”跳转。

- 顶部标题与整体连接状态，显示当前主机名称、MAC、主机编号。
- **上方为日志区域，下方为操作区域**，按默认约40%/60%分配可用高度；两区独立滚动，不能把日志放在长表单末尾。
- 日志区：TX/RX/状态与错误、时间、清空、原始JSON开关；用户浏览历史时不强制跳到最新。
- 下方操作区：扫描/按编号连接、MTU/载荷与风险提示、白名单输入、一键关机与结果、探测器事件列表和清空、断开/重新建立会话。
- 事件列表保持最新在上，复用原事件类型与配色；保留独立清空，不与日志清空混为一项。
- 操作区内的事件RecyclerView采用有界可见高度，避免同向无限嵌套测量导致列表全部展开。
- 横屏、小屏、键盘弹起、API35及以上窗口Insets需在实际屏幕验证，不把固定dp高直接当作跨设备完成。

此布局为本开发文档的默认设计，不要求逐像素复制原 `activity_xcfiber_check.xml`；原布局将事件/日志各分一半的做法可复用控件，不保留其与新布局冲突的层级。

### 5.3 native、混淆与交付约束

- `libmkdxcfiberchecklib.so`只提供cJSON帧判定，应用层不主动调用native接口。
- 当前业务AAR实际包含 `arm64-v8a`、`armeabi-v7a`、`x86`、`x86_64` 的libmkdxcfiberchecklib.so；BLE AAR无jni目录/so。该事实取自实物，不再仅根据源码未配置abiFilters推断。包中有某ABI不等于已在对应设备/模拟器验证可用，也不保证其他未来依赖支持该架构。
- AAR消费者无需配置SDK native源码/CMake路径。当前实物arm64-v8a与x86_64的ELF PT_LOAD段p_align为16384，两个32位ABI为4096。仅属ELF静态对齐观察，不是最终APK/AAB的zip对齐、动态链接依赖或16KB页设备加载成功证明；实际兼容仍需验证。
- 当前业务AAR中的proguard.txt已包含保留XcJsonNative和native成员的规则，BLE AAR的proguard.txt为空；最终混淆release仍需核查BLE反射事件派发。若需临时保守keep，应记录原因和验证结果。
- SO加载失败时会退回JavaFrameProbe；SO已加载但frameLength调用出错时，safe调用返回-1，并不保证自动切换Java。两类行为在故障记录中分开，不能把降级称为兼容性通过。
- 新项目无需SDK AppID/AppSecret；不能复制其他App中的授权常量或新增“本地鉴权输入页”。

## 6. 功能与SDK调用映射

唯一设备SDK入口：`com.makeid.mkdxcfiberchecklib.XCFiberCheckManager`。业务controller管理进程内单例，不直接操作DefaultBLE内部连接表、观察者或协议常量来旁路正常API。

| 功能 | API | 约束 |
| --- | --- | --- |
| 初始化 | `getInstance()` / `init(Application)` | 首次进入业务、权限/硬件条件检查后调用，配置前缀和观察者 |
| 扫描 | `startScan(long timeoutMillis, ScanListener)` | 默认15秒，重复调用会替换旧扫描；使用BLE库ScanListener，不混用锁库接口 |
| 停止/查询扫描 | `stopScan()` / `isScanning()` | stop为异步投递，getter不是动作完成通知 |
| 选设备连接 | `connect(Device, XCConnectListener)` | 用户选择后执行，SDK会断开已有连接 |
| 地址连接 | `connect(String address, XCConnectListener)` | 可保留为说明/手工扩展；先校验合法MAC、权限与硬件，不按探测器ID连接 |
| 主机编号连接 | `connectByDeviceId(String, XCConnectListener)` / 三参超时重载 | 扫描匹配主机，不是按探测器连接；也必须先检查权限 |
| 状态 | `isConnected()` / `isReady()` | 已连接不等于通知就绪，写操作以onReady和本地事务状态为准 |
| MTU/载荷 | `getMtuSize()` / `getPackageSize()` | 初始23/20，可能是旧记录；当前会话以onReady实参展示，清断线UI |
| 功率变化 | `setOnPowerChangeListener(OnPowerChangeListener)` | `(String deviceId, boolean powerUp)`，不是dBm数值 |
| 探测器开/关机 | `setOnDevicePowerListener(OnDevicePowerListener)` | 与主机BLE断线/关机结果分开 |
| 调试原文 | `setRawJsonListener(RawJsonListener)` | 发送提交/完整JSON接收，不代表GATT成功或ACK |
| 过滤 | `setDeviceIdFilter(String...)` / Collection重载 | 拦截业务上报，不是访问控制；null重载显式类型或用clear方法 |
| 过滤查询/清空 | `getDeviceIdFilter()` / `isDeviceIdFilterEnabled()` / `clearDeviceIdFilter()` | 不可变快照，空表示全部放行 |
| 一键关机 | `shutdownAll(XCCommandCallback)` | 用户二次确认后发送，SDK有5000ms命令超时 |
| 断开/释放 | `disconnect()` / `release()` | 异步执行，退出需要额外清listener/白名单和停止扫描 |

所有设置/调用归一到应用主线程；正常连接、业务事件、关机结果经SDK主Handler派发，但普通扫描直接转发底层，地址连接早期失败可能同步回调，不能继承旧Activity“所有回调都在主线程”的假设。

### 6.1 身份与过滤规则

| 名称 | 示例 | 用途 |
| --- | --- | --- |
| 主机BLE名称 | TR-FID-000002 | 手机连接的实际BLE设备名 |
| 主机编号 | 000002 | connectByDeviceId目标；接受完整TR-FID名称，trim/去前缀后忽略大小写 |
| 主机MAC | AA:BB:CC:DD:EE:FF | 扫描选择/合法地址连接；不是业务编号 |
| 探测器ID | 000011、A-1 | `content.device_id`，RFID/二维码标签编码、过滤键 |

编号/ID始终作为字符串，保留前导零，不自动去掉连字符。白名单trim后忽略大小写，`A-1`与`A1`、`000011`与`11`均不同。空列表、null或全空白关闭过滤；非空时缺失ID也被拦截。关机ACK无须命中ID，原始JSON也不受过滤影响。

原输入解析容忍半/全角逗号、分号和空白分隔；迁移版保留该行为并明确“输入空白视为列表分隔”，不是SDK会自动去掉ID内部符号。`XcDevice.serialNo()`按精确前缀截取，与connectByDeviceId的大小写容忍略有差异，显示异常不能据此连接另一个设备。

### 6.2 功率变化事件的解释

- SDK兼容部分cmd、键名和power_change值的拼写差异，业务不新增第二套协议解析器。
- 当前unknown/missing的power_change可能表现为 `powerUp=false`；UI显示“power_down/非up（请结合原文）”，不能强称每个false都是有效物理下降。
- 事件详情保留设备ID、时间、类型、所属主机会话；若需严格区分未知值，应另立SDK扩展任务，不能在App读取另一个原文队列凭时序猜对应关系。
- 未知cmd、无listener、被白名单过滤分别提示/记录，不把“收到原文”当作必然产生业务事件。

## 7. 连接、状态与生命周期

### 7.1 状态机

```text
IDLE
  → WAITING_PERMISSION
  → INITIALIZING
  → SCANNING / SCANNING_FOR_HOST_ID
  → CONNECTING
  → SERVICE_DISCOVERED
  → READY
  → COMMAND_PENDING
  → READY / RESULT_UNKNOWN / DISCONNECTED
  → CLOSING
  → IDLE
```

- `onConnected`表示服务发现，SDK接着请求MTU512，再开启FFE4通知；仅onReady使能关机。
- MTU失败可按默认值继续通知，不把请求512当实际值。载荷小于21字节时显示分包验证提示，但不自行截短命令或改写WriteOptions。
- 整体就绪流程增加应用总截止时间，建议40秒（按编号15秒扫描+连接/通知）；不是SDK协议承诺。通知失败未必立即onFailed，不能永久等待。
- 当前关闭自动重连；用户可主动重新选择主机，SDK不能在关机后自动把设备连回来。
- 只允许一轮扫描/匹配/连接，进行中禁止开启另一轮或切目标；关机等待中禁止连接、扫描、释放外的冲突操作。

### 7.2 单一owner与扫描页交接

**扫描页不是第二个SDK所有者。** 默认采用薄Controller + 扫描页的方式保留原用户选设备体验：

1. 主页面初始化唯一SDK会话、记录owner/sessionId。
2. 用户申请权限后明确进入扫描页，主页面标记正在执行“扫描子流程”。
3. 扫描页只调用已有会话的扫描API并注册本轮扫描listener，不init、不release。
4. 选择/返回/停止时结束本轮扫描，返回选中Device与本轮requestId；取消不连接。
5. 主页面核对仍属当前session/requestId、处于允许连接状态且权限有效，随后连接；不采信上一会话的ActivityResult。

不能把主页面每次onStop都无条件release：打开扫描Activity也会触发onStop，会使自己的扫描链路失效。区分“由本App发起扫描子流程”“权限弹窗/系统设置”“真正退后台/用户退出”。同样不能因为设置了子流程标志就永久保活：扫描页真实退后台应停止扫描并结束会话，回前台重新确认。

推荐两页共同上报前后台状态至同一owner。实现中可用应用级Activity生命周期可见计数/明确扫描导航状态，处理配置变更时短暂零可见窗口；不得凭单个Activity布尔值猜测整个App可见性。SDK不需因此变成长期后台服务。

### 7.3 迟到回调与释放

- 每个连接监听、扫描结果、ActivityResult、超时任务、关机结果在**注册时**固定sessionId/scanId/operationId；投递主线程后再次核对。
- `connectByDeviceId`找不到主机有扫描周期额外3秒的兜底，但其局部任务不在release统一取消范围，退出后可能仍失败。失效UI回调不等于已取消SDK内部任务。
- SDK可能先排队停止扫描/连接等动作。应用token不能识别“旧底层事件已经被新SDK listener接收”这一类来源污染，不能把token当万能隔离。
- 首版禁止并发或快速连续匹配/换主机；先stopScan/release，按主Handler队列完成清理后再init/注册新listener。如果旧请求已在SDK队列中，待该轮终结/清理，不能只递增token立即启动新连接。
- release不自动清应用设置的三类数据listener和ID白名单，也不等于stopScan；先标记CLOSING、停止扫描、listener设null、清白名单、释放，最后再转IDLE。
- 当前API没有“release完成”回调。Controller应在主线程按SDK实际post顺序安排清理与后续初始化，并验证观察者/连接交接；不能通过固定sleep宣称完全清理。
- 断线重连时事件按会话分段或清空；旧记录不得继续显示成新主机刚上报。批量全清日志由用户决定，不借机删掉诊断错误。

## 8. 一键关机流程与安全边界

```text
用户点击“一键关机”
  → 确认session、onReady、无在途命令
  → 弹窗显示当前主机名/编号/MAC及“全部”影响范围
  → 用户明确确认
  → COMMAND_PENDING，禁用重复点击与换目标
  → manager.shutdownAll(callback)
  → ACK成功 / 设备拒绝 / 5秒超时 / 断线 / 释放
  → 单次终结UI，记录结果，绝不自动重发
```

- 白名单仅过滤手机收到的业务事件，**不限制关机影响范围**。弹窗必须说明，不能显示“只关白名单设备”。
- SDK仅将status等于ok（忽略大小写）判断成功，其他/空/未知失败。GATT写成功不是业务成功。
- SDK用finishPending统一移除挂起命令，避免同一请求ACK后断线再次失败回调。但协议无请求序号，新旧重复发送的迟到ACK不能可靠区分，因此应用仍必须防重复与串行操作。
- 5000ms自SDK登记命令开始，包括等待写入/ACK；不承诺正常ACK几十毫秒必达。
- 成功表示收到设备确认，不等于已核验每个探测器物理断电。断线/超时表示确认不足，不证明设备未执行；显示“结果未知，请现场核实”。
- 显示并记录错误原文，例如 `not ready`、`timeout waiting for ACK`、`disconnected before ACK`、`rejected: status=...`、`superseded by a new request`、`sdk released`，不假造统一数字错误码。
- 关机失败/超时后不自动恢复发送，用户先核对设备与会话；断开后由用户重连，不能自动补发旧操作。

## 9. 权限、离线与数据策略

### 9.1 权限边界

| 条件 | 所需能力 | 应用行为 |
| --- | --- | --- |
| API31及以上BLE | BLUETOOTH_SCAN、BLUETOOTH_CONNECT | 扫描页和按编号连接共用同一个权限入口；未授权不调用SDK对应动作 |
| API23～30 BLE | 定位权限、定位服务 | 按系统/target约束请求，明确引导打开系统定位 |
| API21～22 | Manifest普通蓝牙权限 | 不弹运行时权限框，检查硬件/蓝牙开关 |
| 不支持BLE/蓝牙关闭 | 系统硬件/设置 | 明确说明，不进入无限连接等待 |

Manifest需声明新Activity，非启动页exported=false；只使用蓝牙所需权限，不加入USB/NFC/相机/存储/安装包/录音权限。SDK Manifest为空，但配套BLE库会合并权限，最终以Merged Manifest为准。

如采用neverForLocation，必须真实不从扫描推导位置，并用实际TR-FID广播验证可能的过滤影响；不能无条件复制声明。本App不静默打开蓝牙，系统权限撤销或设置返回应重新检查。

targetSdk36的新工程涉及系统广播、BLE权限、Insets/边到边与ActivityResult行为，原SDK编译API34不是这些行为已兼容的证据。先用目标系统验证，遇到底层兼容问题由SDK修复并重新交付；不能未经确认静默把target降到34掩盖问题，也不默认在迁移任务升级SDK所有模块。

### 9.2 运行时离线与隐私

- 不迁移BaseApplication、HttpUtil、Retrofit/OkHttp、Token、Bugly、后台上报或旧服务器资源。
- 最终Manifest不保留INTERNET；代码也无可执行IP网络请求，不以“权限不足所以请求失败”作为唯一离线保证。
- 没有AppID/AppSecret、密钥申请页面；不要引入锁Demo的配置类或签名/账号文件。
- 默认仅内存保留白名单、事件和日志，退出清会话状态；默认不记录到共享存储。将来允许导出应由用户触发、脱敏并使用FileProvider，不申请全盘权限。
- 原始JSON可能含设备标签编码等身份信息；原文调试开关和SDK DEBUG分开管理。MkdXCFiberCheckLog.DEBUG不会关闭RawJsonListener或底层全部BLE日志。
- 如为设备编号提供本地记忆，仅保存用户确认的非敏感偏好并明确清理入口；不能把上一会话的主机和就绪状态自动恢复成可关机。

## 10. 原实现必须修正或补齐的差异

| 原实现观察 | 迁移要求 |
| --- | --- |
| 按编号连接直接读输入并调用SDK，不共用扫描页权限申请 | 两种入口权限/硬件检查一致 |
| 扫描列表每次广播直接add | 按MAC更新同项RSSI，数量统计唯一设备，不让重复广播淹没列表 |
| 关机按钮没有明确二次确认，等待中可重复点击 | 目标/全部范围确认、COMMAND_PENDING与唯一完成出口 |
| release按钮只把UI设未连接，后续仍可直接调用SDK | 区分IDLE/CLOSING/RELEASED，后续重新init后才能扫描/连接 |
| onDestroy仅移除数据listener，未完成整轮资源清理 | 单一owner统一stopScan、清过滤/listener、结束等待与release |
| 页面注释假定所有回调主线程 | 扫描/早期失败统一投递UI线程，注册时捕获会话 |
| log方法始终scrollToPosition(0) | 阅读历史时不强制跳转，跟随开关/滚动位置判定 |
| 时间用当前毫秒对86400000取模 | 使用本地时区时间格式，耗时用elapsedRealtime，不把UTC时分当本地时间 |
| 功率false直接显示power_down | 说明缺失/未知可能非up，提供原文排查，不伪造严格物理结论 |
| 开页无条件沿用SDK既有白名单 | 会话开始显式应用当前输入或clear，退出清理；不依赖旧全局状态 |
| 对新工程照抄旧包名/R/Binding资源 | 全部改为新包和新布局命名，不依赖原app源码或生成类 |

迁移不能只以“界面能打开”为完成条件；以上状态/危险操作差异需要先写纯逻辑用例，再由用户进行设备验证。
